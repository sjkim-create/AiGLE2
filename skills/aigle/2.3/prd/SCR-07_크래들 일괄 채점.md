# [SCR-07] 크래들 일괄 채점 기획서

> **문서 성격**: [SCR-01] 채점 관리의 **크래들(스마트펜) 일괄 채점 기획 전용 문서**다. SCR-01에는 요약 이력만 남기고 상세는 본 문서가 정본(single source)이다.
> **기술 범위**: 화면의 흐름 · 상태별 정책 · 기능 규칙만 기술한다. 색상·치수 같은 디자인 요소와 구현(함수·변수·컴포넌트) 내용은 담지 않는다.
> **동기화 규칙**: 크래들 채점 사양을 변경하면 **본 문서와 SCR-01 이력을 함께 갱신**한다. 펜 판정 규칙 자체는 [POP-28]이 정본이며 본 문서는 그 결과를 화면에서 어떻게 다루는지만 적는다.
> **연계 문서**: [POP-28] 일괄 채점 — 펜 상태 판정 규칙 · [POP-30] AiGLE 필수 프로그램 확인 · [SCR-05] 스캔 일괄 채점(같은 Step 구조) · [TSK-05] 답안지 서식

---

## 0. 문서 이력

> 버전 번호는 **SCR-01의 버전을 승계**한다 (별도 채번하지 않음).

- **v4.7** | 2026-09-11 | **크래들 일괄 채점 기획을 SCR-01에서 분리해 신규 작성** — 4-Step 워크플로우와 아래 결정을 정본화
  - **① 크래들 3대 × 10구 = 30자루**: 슬롯 번호는 실물처럼 크래들마다 1~10으로 표시한다 (§4.2)
  - **② 필수 프로그램 확인은 [설치 확인] → 실행 중 → 준비 완료 한 흐름**: 별도 [실행] 단계 없음 (§4.1)
  - **③ 2단계 읽는 중 화면은 프로그레스 바 + 순환 타이틀**: 단계별 카드 목록 폐기 (§5.1)
  - **④ 답안지 기재란 OCR 대조 폐기**: 채점 전 OCR 판독 단계가 끼면 채점이 늦어지고, 오판이면 어차피 답안을 봐야 한다. 처음부터 답안지 이미지를 크게 보여 준다 (§5.4)
  - **⑤ 「번호표 재체크 후 재거치」 폐기 → 직접 매칭**: 답안을 보고 학생을 고르면 그 자리에서 매칭된다. 단위는 페이지가 아니라 **반(북코드) 답안 묶음** (§5.5)
  - **⑥ 직접 매칭은 선택 그룹 북코드 답안지에서만**: 다른 반 북코드 답안지는 열람만 하고 매칭 버튼은 비활성 (§5.5)
  - **⑦ 카운트는 배지 색 기준**: 확인 필요 = 동기화 불가 + 중복, 대상 아님 = 데이터 없음 (§5.2)
  - **⑧ 목록 순서는 판정 시점에 고정**: 매칭으로 상태가 바뀌어도 행이 이동하지 않는다 (§5.3)
  - **⑨ POP-28 #10 문구 개정**: `펜 연결` → `답안 없음 — 답안지 미작성` (§5.2, POP-28 개정 필요)
  - **⑩ 완료 화면 3줄**: 완료 · 채점 문항 N건 학생 N명 · [확인] 안내 (§7)
  - **폐기**: 「펜 없는 학생」 카운트와 「답안 찾기」 모드, 우측 패널의 펜·학생·배지 정보 헤더, 「다른 기록」(번호표 격자·다른 그룹 필기) 토글, 「설치 완료 → [실행]」 중간 화면, MAC 주소 열, 모달 헤더의 북코드 표기

## 1. 화면 개요

- **화면 ID**: SCR-07 (SCR-01 내 모달 워크플로우)
- **호출 위치**: SCR-01 미채점 탭 → **[🖊 크래들 일괄채점 (N명)]**
- **비즈니스 목적**: 크래들에 거치된 스마트펜의 오프라인 필기를 읽어 선택한 그룹의 학생과 매핑하고 AI 일괄 채점까지 이어간다. 스캔 채점([SCR-05])과 같은 Step 구조를 쓴다
- **핵심 아이디어**: **학생 식별의 근거는 번호표 체크 위치**(POP-28)다. 번호표를 잘못 찍은 휴먼 에러는 교사가 **답안지를 눈으로 보고** 같은 그룹 안에서 바로잡는다. 시스템이 기재란을 읽지(OCR) 않는다
- **권한**: 교사 전용

## 2. 주요 사용자 흐름

1. SCR-01 미채점 탭에서 그룹 선택 → 학생 체크 → **[크래들 일괄채점 (N명)]**
2. **크래들 연결** — AiGLE Connect 확인(자동 실행) → 펜 거치 → 연결 확인
3. **[🔗 데이터 매핑 시작]** → 펜 데이터를 읽어 판정(POP-28)
4. **데이터 매핑** — 확인 필요 펜은 답안을 보고 학생을 직접 매칭
5. **[채점 시작]** → AI 채점 프로그레스 (창을 닫으면 최소화)
6. 완료 → **[확인]** → 채점된 학생이 「채점 확인」 단계로 이동

## 4. Step 1 — 크래들 연결

### 4.1 필수 프로그램 확인 ([POP-30])

- 모달을 열면 AiGLE Connect 실행 여부를 1회 확인한다. 실행 중이 아니면 **필수 프로그램 확인 창이 바로 뜬다**
- 흐름: **[설치 확인] → 실행 중… → 준비 완료**. 설치가 확인되면 곧바로 실행으로 넘어가며 **별도 [실행] 버튼 단계는 없다**
  - 헤드라인: 확인 중 `설치가 확인되어 프로그램을 실행하고 있어요.` → 완료 `필수 프로그램이 모두 실행 중이에요.`
  - 미설치: `필수 프로그램이 설치되어 있지 않아요. 확인해주세요.` → [다운로드] → 설치 완료 후 자동 실행 → 준비 완료
  - 실행 실패: `프로그램이 켜지지 않았어요. 직접 실행한 뒤 다시 확인해주세요.` → [다시 실행] + `바탕화면·작업 표시줄에서 AiGLE Connect를 실행한 뒤 [다시 실행]을 눌러 주세요.`
- 목록에는 Ncode Print Doctor도 남기되 **흐리게 표시하고 조작을 막는다** (이 화면의 필수 요건이 아님)
- 준비 완료 후 [확인]으로 닫으면 크래들 연결 화면이 활성화된다. 실행 상태는 상위(환경설정)가 기억하므로 다음 진입부터는 이 창이 뜨지 않는다

### 4.2 크래들 구성

- **크래들 3대 × 10구 = 30자루**. 화면에 3대를 나란히 그린다
- **슬롯 번호는 크래들마다 1~10** (실물에 11~30이 없다). 내부 식별은 통번호를 쓰되 화면·툴팁은 `크래들 2 · 3번` 형식
- 크래들 헤더: `크래들 N · 연결됨 · 거치수/10`
- 안내: `🔌 크래들에 펜을 거치해 주세요. 여기서는 펜 연결만 확인하고, 누구의 답안인지는 다음 단계에서 판별합니다.`
- 슬롯 아래에는 **연결 상태만** 표시한다 (배터리·펌웨어는 목록이 맡는다)

### 4.3 연결 상태 3종

| 상태 | 표시 | 의미 · 처리 |
|:--|:--|:--|
| 연결 중 | `연결 중` | 거치 직후. 곧 연결/실패로 바뀐다 |
| 연결 | `연결` | 정상. 연결 완료 수·판정 대상에 포함 |
| 실패 | `실패` | 접촉 불량 등. 연결 완료 수에서 빠지고 판정 대상이 아니다. **뺐다가 다시 꽂으면** 정상 연결된다 |

- 실패가 1개라도 있으면 안내 카드에 `⚠ 연결 실패한 펜은 뺐다가 다시 꽂아 주세요.`, 요약 줄에 `연결 실패 N개`
- 요약 줄: `거치 N / 30개 · 연결 완료 N개 (· 연결 실패 N개) (· 펌웨어 업데이트 N개)`

### 4.4 연결된 펜 목록

- **크래들 1 / 2 / 3 세 열**로 나눠 표시. 열 머리 `크래들 N · 거치수/10`, 거치된 펜이 없으면 `거치된 펜 없음`
- 항목: 슬롯(1~10) · 펜 ID · 연결 · 배터리 · 펌웨어. **MAC 주소는 표시하지 않는다**
- 펌웨어가 구버전이면 [업데이트] (개별) / [↺ 펌웨어 일괄 업데이트 (선택)]. **업데이트는 채점의 필수 요건이 아니다**

### 4.5 다음 단계 조건

- [🔗 데이터 매핑 시작] 활성: AiGLE Connect 준비 완료 **and** 연결된 펜 1자루 이상
- 푸터 고지(펜 0자루): `크래들에 펜을 1자루 이상 거치해야 다음 단계로 넘어갑니다.`

## 5. Step 2 — 데이터 매핑

### 5.1 읽는 중 화면

- 프로그레스 바 1개 + 타이틀이 **`북코드 대조` → `내용 판정` → `중복 검사`** 순으로 일정 간격 순환한다. 실제 판정 단계와 묶지 않는다 — "이런 일을 처리하고 있다"만 보이면 되고, 단계가 넘어가는 느낌을 주면 교사가 각 단계의 길이를 읽으려 든다
- 문구: `펜 데이터를 읽고 있습니다.` / `거치된 N자루의 필기를 확인합니다.` / `{타이틀} 처리 중…`
- 舊 3단계 카드 목록(✓/●/○ 전환 · 브릿지 호출명 · 비용 배지)은 폐기

### 5.2 판정과 카운트

- 판정 규칙·배지·진행 문구는 **[POP-28]이 정본**이다. 본 문서는 아래 한 건만 개정한다
  - **#10 (번호표는 찍었는데 답안을 안 썼다)**: 배지 `데이터 없음` 유지, 진행 문구 `펜 연결` → **`답안 없음 — 답안지 미작성`**. 舊 문구는 #11 정상 흐름의 첫 상태와 같아 "데이터가 없는데 연결됐다?"로 읽혔다
  - 그룹 불일치 표기는 정본대로 `그룹 불일치 [감지: 1-2반 → 선택: 1-1반]`. 반이 여럿이면 `감지: 1-2반·1-3반·1-4반·1-5반`
- **카운트 3종** (미니 크래들 아래): 배지 색과 같은 기준으로 센다

| 카운트 | 기준 |
|:--|:--|
| 🟢 채점 대상 | 정상(#11) 펜에 붙은 학생 수 |
| 확인 필요 | 빨강 — 동기화 불가(#2·3·5·6·7·8) + 중복(#9) 펜 수 |
| 대상 아님 | 회색 — 데이터 없음(#1·#10) 펜 수 |

- 학생 표기는 어디서나 **`학년-반-번호 이름`** (예: `1-1-12 김민지`)

### 5.3 화면 구성 — 좌 50 : 우 50 고정

- 왼쪽 열: 미니 크래들 3대 → 카운트 줄 + [↻ 다시 읽기] → 펜 목록. 오른쪽: 답안 뷰어가 2단계 영역의 맨 위부터 맨 아래까지 차지한다
- 펜을 골라도 좌우 폭이 바뀌지 않는다
- **펜 목록** 열: 펜(펜 ID + `크래들 N · M번`) · 학생 · 배지 · 채점 진행
  - 행 배경은 물들이지 않는다 — 상태는 배지 색(회색·빨강·초록)만으로 읽는다
  - **순서는 판정이 끝난 시점에 한 번만 고정**: 확인 필요 → 정상 → 대상 아님, 그 안에서 슬롯 순. 직접 매칭으로 상태가 바뀌어도 **행은 그 자리에서 배지·문구만 바뀐다**. 순서는 [다시 읽기]로 판정을 다시 돌릴 때만 새로 잡히고, 판정 뒤 새로 꽂은 펜은 맨 아래에 붙는다
  - **선택된 행에만 [⏏] 펜 빼기**가 보인다. 누르면 펜이 크래들·목록에서 빠지고 선택이 해제된다. 다시 꽂는 것은 1단계([← 펜 다시 거치])에서
- **[↻ 다시 읽기]**: 판정을 처음부터 다시 돌린다. **직접 매칭 기록은 유지**된다
- **구성 변경 배너**: 판정 이후 펜을 빼거나 꽂으면 `🔄 크래들 구성이 바뀌었습니다 — 아직 읽지 않은 펜 N자루. 펜을 다시 거치했다면 [↻ 다시 읽기]를 눌러 주세요.` + [다시 읽기]가 강조된다. 2단계 판정은 다운로드를 동반해 비싸므로 자동으로 다시 돌리지 않는다

### 5.4 오른쪽 — 답안 뷰어

- 펜 미선택: `왼쪽에서 펜을 선택하면 그 펜에 담긴 답안을 크게 볼 수 있습니다.`
- 펜을 고르면 **답안지 이미지**(펜 필기를 답안지 서식 위에 렌더한 결과)를 패널 폭에 맞춰 띄운다. 기재란·문항·답안이 모두 이미지 안에 있으므로 따로 그리지 않는다. 툴바는 `◀ 1/N ▶ … 문항명 · n/m장`뿐
- **우측에는 펜·학생·배지 정보를 다시 쓰지 않는다** — 왼쪽 행이 이미 말하고 있다. 여기는 답안을 크게 보는 자리이고, 조치는 왼쪽에서 고른 펜에 적용된다
- **보이는 범위 (반 단위)**

| 펜 상태 | 뷰어에 보이는 답안 |
|:--|:--|
| 정상 · 직접 매칭됨 | 선택 그룹(매칭한 반) 답안지만 |
| 확인 필요 · 대상 아님 | 이 과제의 모든 반 답안 묶음을 **반 탭**으로 (`1학년 2반 답안 4장` …). 페이지를 섞어 넘기지 않는다. **다른 과제 데이터는 어떤 경우에도 보이지 않는다** |

- 답안이 없는 펜: `이 펜에는 이 과제에 쓴 답안이 없습니다.`
- 舊 「번호표 격자·다른 그룹 필기」 토글, 「답안지/다른 기록」 배지, 「답안지 기재란 ↔ 번호표 판독」 OCR 대조 카드는 폐기

### 5.5 직접 매칭

- **원칙**: 학생 식별의 근거는 번호표 체크 위치다. 번호표를 잘못 찍은 휴먼 에러(미체크·판독 불가·중복 등)는 교사가 **같은 그룹 답안지**를 보고 실제 학생으로 매핑한다
- **범위**: **선택 그룹 북코드의 답안 묶음에서만** 매칭된다. 다른 반 북코드 답안지는 열람만 하고 매칭 버튼은 비활성 — 그 답안은 그 반 채점 때 처리된다
- **단위**: 페이지가 아니라 **반(북코드) 답안 묶음**. 한 북코드 안의 이 과제 답안 페이지는 서식상 고정된 묶음이라 교사가 장을 고를 필요가 없다
- **조작**: 뷰어 위 안내줄에 `이 답안을 [학생 ▾]의 답안으로 채점 [✓ 매칭]`. 학생을 고르기 전에는 버튼 비활성
- **결과**: 판정이 즉시 다시 계산된다([다시 읽기] 불필요). 배지 `정상`, 진행 `펜 연결 · 직접 매칭`, 뷰어 안내 `✓ 직접 매칭 — {학생}의 답안으로 채점됩니다 ({반} 답안지) [매칭 해제]`. 같은 학생에 두 펜이 붙으면 기존 중복 검사가 그대로 잡는다
- **해제**: 채점 시작 전까지 [매칭 해제]로 되돌릴 수 있다
- **기록**: 매칭 결과는 업로드에 함께 기록되고 채점 후 펜 파일이 지워지므로 "다시 읽으면 되살아난다"는 문제가 없다
- 舊 「번호표 다시 체크 후 재거치」 에뮬레이터, 「펜 없는 학생 → 답안 찾기」 모드는 폐기

### 5.6 상태별 안내 문구 (뷰어 위 안내줄)

| 펜 상태 | 안내 | 매칭 |
|:--|:--|:--|
| 정상 | (없음) | — |
| 직접 매칭됨 | `✓ 직접 매칭 — {학생}의 답안으로 채점됩니다 ({반} 답안지)` + [매칭 해제] | — |
| 중복 데이터 | `같은 학생에 두 펜이 붙었습니다. 답안을 확인하고, 학생을 고르세요.` | 선택 그룹 답안지에서 가능 |
| 번호표 미체크 · 판독 불가 · 명단 밖 · 미선택 | `번호표로 학생을 찾지 못했습니다. 답안을 확인하고, 학생을 고르세요.` | 선택 그룹 답안지에서 가능 |
| 그룹 불일치 | `{그룹} 답안지가 아닙니다. 다른 반 답안지에 쓴 답안이라 이 그룹에서는 채점할 수 없습니다.` / `어느 반 답안지인지 아래에서 확인하세요. 우리 반 학생이면 {그룹} 답안지에 다시 쓰게 해 주세요.` | 불가 |
| 다른 반 탭을 보고 있을 때 | `{다른 반} 답안지입니다. {그룹} 학생에게는 매칭할 수 없습니다 — 다른 반 답안은 그 반 채점 때 처리됩니다.` + 비활성 [✓ 매칭] | 불가 |
| 필기 없음 | `이 펜에는 필기가 없습니다.` | — |

### 5.7 채점 시작 차단

- **차단 조건**: 중복 데이터가 남아 있거나 채점 대상이 0명일 때. 미매칭 펜·미연결 학생은 **차단하지 않는다** — 크래들에 없는 학생은 자연 제외이고, 미매칭 펜은 이 그룹 데이터가 아닐 수 있어 강제할 근거가 없다
- 푸터 문구
  - 중복: `⚠ 중복 데이터 N개를 먼저 풀어 주세요. 답안을 보고 잘못 붙은 펜을 진짜 주인에게 직접 매칭하면 풀립니다.`
  - 대상 0: `⚠ 채점할 수 있는 펜이 없습니다. 펜을 거치한 뒤 [다시 읽기]를 누르거나, 답안을 보고 학생을 직접 매칭해 주세요.`
  - 통과·미연결 학생 있음: `⚠ 펜이 연결되지 않은 N명은 채점 대상에서 제외됩니다.`
- 푸터 버튼: [← 펜 다시 거치](1단계 복귀, 판정·매칭 유지) · [채점 시작]

## 6. Step 3 — AI 일괄 채점

- `AI가 채점하고 있어요.` / `학생 N명 · 문항 N건을 채점 중입니다.` + 진행률
- 펜별 상태 전이는 POP-28 #11·#12: `펜 연결 → AI 채점중 → AI 채점 완료`, 업로드가 끝난 펜은 배지가 `데이터 삭제`로 바뀐다 (실패가 아니라 정상 완료의 흔적)
- 창을 닫으면 최소화(§3). 진행 상태·판정 결과·매칭이 모두 보존된다

---

## 7. Step 4 — 완료

세 줄만 표시한다.

1. **완료**
2. `채점 문항 N건 · 학생 N명`
3. `[확인]을 누르면 「채점 확인」 단계로 이동합니다.`

- [확인] → 채점된 학생이 `채점 확인`으로 이동하고 「채점 확인」 탭으로 전환한다
- 미연결 학생·잔류 펜 고지는 표시하지 않는다 (2단계 푸터에서 이미 고지)

---

## 8. 데이터 정책

- 판정에 쓰는 데이터(내 북코드 · 형제 북코드 · 그룹 명단 · 번호표)는 [POP-28] §2를 따른다
- 채점(업로드)이 끝난 펜의 파일은 삭제된다. 채점에 올라가지 못한 펜의 필기는 펜에 그대로 남는다
- 직접 매칭 결과는 펜 ID + 북코드 기준으로 업로드에 함께 기록한다

## 9. 미구현·제약

- **에뮬레이터 요소**(프로토타입 한정): 슬롯 클릭 거치/제거, [🧪 전체 거치]/[전체 제거], 첫 거치에서 한 번 연결 실패하는 펜, 펌웨어 업데이트 진행률, 답안지 샘플 이미지 1장과 기재란 손글씨 오버레이. 실서비스에서는 거치·제거가 물리 동작이고 답안지 이미지는 펜별·장별 렌더 결과가 들어온다
- **#10 세분화 보류**: 답안 없음의 원인(다른 반 답안지에 작성 · 다른 과제 답안지 · 펜 교체 등)을 문구로 갈라 보이는 안은 POP-28 개정과 함께 다룬다. 채점 완료로 삭제된 펜은 #1과 구분할 수 없다(POP-28 §7)
- **반 전체가 다른 반 답안지에 쓴 경우**: 규칙상 전원 #10 `답안 없음 — 답안지 미작성`이 되어 채점할 수 없다. 세션 단위 예외(다른 반 답안지를 이 그룹 답안으로 인정) 도입 여부는 미결
- **같은 북코드 종이에 두 학생 글씨가 겹친 경우**(잘못 받은 종이 + 공용 펜): 소프트웨어로 분리할 수 없다. 뷰어에서 겹침이 보이면 재작성 안내
