# 스마트 과제 등록(정답형) — AI 추출 설계 기준 · 요청 문구

> **용도**: 개발자 전달용. 프로토에서 검증한 AI 판단 기준·요청 문구·후처리 규칙을 상용 구현의 출발점으로 쓴다.
> **위치**: 프로토 로컬 코드 `src/lib/itemExtract.js` · `src/lib/taskFromFile.js` (브라우저 → Gemini 직접 호출, 프로토 한정)
> **상용 원칙**: 요청 문구는 서버(프롬프트 관리 체계)에서 관리하고 클라이언트에 두지 않는다. API 키도 서버에만 둔다.
> 관련: PRD `TSK-14 스마트 과제 등록` · `QBK-01 문제 은행` · DB 설계 `문제은행_DB설계.md`
> 작성 2026-10-02 · 상태: 초안 (프로토 검증 2건 — §7)

## 1. 처리 흐름

```
[자료 PDF·이미지]
  → ① 쪽 이미지 렌더 (PDF 앞 10쪽, 가로 1400px JPEG)
  → ② 1차 AI: 문항 추출·유형 분류·정답·메타 (이미지 + 요청 문구 A)
  → ③ 교과 확정: 교육과정 카탈로그 매칭 (성취기준 코드 → 없으면 학교급·학년군·교과명)
  → ④ 2차 AI: 단원 배정 — 과목의 단원 목록 안에서 고르기 (글자만, 요청 문구 B) ※ 기초학력 자료는 생략
  → ⑤ 후처리: 정답 정리·출처 판정·단원 판정·그림 자르기·확인 항목
  → [교사 확인·선택] → 문제 은행 저장 (→ 문제집)
```

## 2. 설계 원칙 (판단 기준)

| # | 원칙 | 근거 |
|---|---|---|
| 1 | **자료에 있는 것만 옮긴다.** 없는 값은 비워 두고 「확인 항목」으로 알린다 | 지어낸 메타데이터가 문제 은행을 오염시키지 않게 |
| 2 | **정답 출처를 남긴다** — `file`(정답표·해설) / `ai`(AI가 풂) / `teacher`(교사 확인) / `none` | AI 추정 정답은 교사 확인 대상 |
| 3 | **정답표가 없으면 AI가 직접 푼다** (`ai`). 판단 불가일 때만 `none` | 기초학력 교재 등 정답표 없는 자료가 많음 |
| 4 | **성취기준은 문항별로 매칭하지 않는다 — 단원 단위** (교과 문항) | 현장 실무: 성취기준은 시험 범위 단원 단위로 다룸. 성취기준 1개 ≈ 2~3차시, 단원 ≈ 2~4개 |
| 5 | **단원은 목록 안에서 고른다** — AI가 단원 이름을 지어내지 않게 | 교육과정 개정(2015↔2022)·출판사마다 단원 표기가 달라 이름 매칭이 실패함 (예: AI가 「힘과 운동」(2015) 생성 → 2022 목록에 없음) |
| 6 | **교과서 대단원명을 그대로 믿지 않는다** — 내용으로 판단한 단원과 맞춰 본다 | 예: 교과서 「Ⅳ. 운동과 에너지」 ≠ 2022 교육과정 「운동과 에너지」(등속·낙하). 실제 문항은 「힘의 작용」 |
| 7 | **기초학력 자료는 단원·성취기준을 요구하지 않는다** — 학습 기능명(skill)으로 관리, 채점은 정답 대조로 동일 | 한글 해득·기초 연산 등은 교과 단원 성취기준에 딱 맞지 않을 수 있음 |
| 8 | **난이도는 쓰지 않는다** | 주관적. 파생 문항은 「목표 학년 + 단원(영역)」 기준 (§6) |
| 9 | **유형을 바꿔도 정답을 지우지 않는다** | 교사가 일괄 변경 후 되돌릴 때 정답 유실 방지 (§5) |

## 3. 문항 유형 (7종)

| key | 이름 | 분류 | 정답 칸 | 판단 기준 (요청 문구에 포함) |
|---|---|---|---|---|
| `multiple_choice` | 선다형 | 선택형 | `choices` (번호, 복수 가능) | 보기 ①②③… 중 고름 |
| `binary_choice` | **양자택일형** | 선택형 | `choices` (1개) | 번호 없이 **두 낱말 중 맞는 것에 동그라미** (예: 그림 옆 「무릎 / 무름」) |
| `true_false` | 진위형 | 선택형 | `truth` | O/X, ○/× |
| `matching` | 연결형 | 선택형 | `pairs` [[왼쪽, 오른쪽]] | 선으로 잇기·짝짓기 |
| `short_answer` | 단답형 | 서답형 | `texts` (허용 답 목록) | 단어·숫자·기호 짧게 쓰기 |
| `completion` | 완성형 | 서답형 | `blanks` (빈칸별 허용 답) | 문장·표 속 빈칸 채우기 |
| `essay` | 서술형 | 서답형 | `model` (모범답안) | 문장으로 서술 — 채점 기준은 과제 배치 단계 |

- 양자택일형은 진위형과 같은 「둘 중 하나」 계열이지만 **낱말 자체에 표시**하므로 답안지 배치·인식이 달라 유형을 분리했다.

## 4. 요청 문구

### 4.1 요청 문구 A — 문항 추출·분류 (1차, 이미지 포함)

- 입력: 쪽 이미지 N장(JPEG) + 아래 문구. `${pageCount}` = 쪽 수, `${fileName}` = 업로드 파일명(단원·학습 기능명 참고)
- 설정: `responseMimeType: application/json`, `temperature: 0.1`

```text
당신은 한국 초·중·고 평가 문항 자료(시험지·문제집·평가지)를 문제 은행으로 옮기는 담당자입니다.
첨부한 ${pageCount}장의 이미지는 하나의 자료를 쪽 순서대로 렌더한 것입니다(1쪽부터). 파일 이름: 「${fileName}」 (단원·학습 기능 이름의 참고 정보)
자료에 있는 문항을 빠짐없이 하나씩 옮기고, 유형을 분류합니다. 없는 내용은 지어내지 마세요.

유형(itemType) — 하나만 고른다
- multiple_choice: 보기(①②③…) 중 고르는 선다형(객관식). 정답이 여럿일 수 있음
- binary_choice: 번호 없이 **두 낱말·표현 중 맞는 것에 동그라미** 치는 양자택일형 (예: 그림 옆 "무릎 / 무름"). 보기는 두 낱말 그대로 choices에 넣음
- true_false: O/X, 맞으면 ○ 틀리면 × 등 진위형
- matching: 왼쪽·오른쪽 항목을 선으로 잇거나 짝짓는 연결형
- short_answer: 단어·숫자·기호 등 짧게 쓰는 단답형
- completion: 문장·표 속 빈칸(   )을 채우는 완성형
- essay: 문장으로 서술하는 서술형·논술형

추출 규칙
- meta: 자료 전체의 schoolLevel(ELEMENTARY|MIDDLE|HIGH|""), studentGrade(적힌 그대로, 예 "3학년"), subject(교과명), title(자료 제목), standardCodes(자료에 적힌 성취기준 코드, 대괄호 없이), scopeUnits(자료에 적힌 시험 범위 단원명 목록)
  - track: 교과 시험·평가지면 "curriculum", 한글 해득·기초 연산·문해력 교재처럼 **기초학력** 자료면 "basic"
  - skill: 기초학력 자료의 학습 기능명 (예 "복잡한 받침 단어 읽기"). 쪽의 활동 이름(예 "읽고 찾기")보다 단원·차시 제목을 쓰고, 쪽에 없으면 파일 이름에서 가져옴. 교과 자료면 ""
- passages: 여러 문항이 함께 보는 공통 지문·자료(예: "[1~3] 다음 글을 읽고"). key는 "P1","P2"…, text는 지문 전문, range는 해당 문항 번호 설명
- items: 문항마다 1개, 자료 순서대로
  - number: 자료의 문항 번호(문자열)
  - itemType: 위 유형 중 하나
  - stem: 발문(질문 문장). 문항마다 발문이 따로 없고 자료 머리에 공통 지시문(예: "읽고 찾기")만 있으면 그 지시문을 넣음
  - material: 발문 아래 <보기>·조건·제시 자료 글 (없으면 "")
  - choices: 선다형·양자택일형 보기 [{"no":1,"text":"..."}] (아니면 [])
  - matching: 연결형이면 {"left":["..."],"right":["..."]} (아니면 null)
  - blanks: 완성형 빈칸 수 (아니면 0)
  - answer: {"choices":[번호…], "truth":true|false|null, "texts":["허용 답…"], "blanks":[["빈칸1 허용 답…"],…], "pairs":[[왼쪽번호,오른쪽번호]…], "model":"서술형 모범답안"} — 해당 유형 칸만 채움
  - answerSource: 정답을 자료의 정답표·해설에서 읽었으면 "file", 정답이 자료에 없어 직접 풀었으면 "ai", 풀 수 없으면 "none"
  - **정답표가 없으면 반드시 직접 풀어 answer를 채우고 answerSource를 "ai"로** 한다 (예: 양자택일형 맞춤법 문제는 표준어·바른 표기를 정답으로). 그림·지문으로도 판단할 수 없을 때만 "none"
  - explanation: 자료에 해설이 있으면 그대로, 없으면 ""
  - points: 자료에 적힌 배점 숫자, 없으면 null
  - unit: 자료에 적힌 이 문항의 단원명 (문항 위 단원 표시·시험 범위 등으로 확인될 때만, 없으면 "")
  - standardCodes: 이 문항에 적힌 성취기준 코드 (없으면 [])
  - passageKey: 공통 지문을 쓰면 그 key, 아니면 null
  - page: 문항이 있는 쪽 번호
  - images: 문항에 딸린 그림·도표·사진 [{"page":쪽,"box_2d":[ymin,xmin,ymax,xmax](0~1000 정규화),"label":"무엇의 그림"}] (장식 아이콘 제외)
- unreadable: 읽을 수 없거나 옮기지 못한 부분을 한 줄씩 (위치 포함)
- isItemSource: 문항이 있는 자료면 true, 아니면 false + reason

JSON만 응답:
{"isItemSource":true,"reason":"","meta":{"schoolLevel":"","studentGrade":"","subject":"","title":"","standardCodes":[],"scopeUnits":[],"track":"curriculum","skill":""},
"passages":[{"key":"P1","text":"","range":""}],
"items":[{"number":"1","itemType":"multiple_choice","stem":"","material":"","choices":[{"no":1,"text":""}],"matching":null,"blanks":0,
"answer":{"choices":[],"truth":null,"texts":[],"blanks":[],"pairs":[],"model":""},"answerSource":"file","explanation":"","points":null,
"unit":"","standardCodes":[],"passageKey":null,"page":1,"images":[]}],
"unreadable":[]}
```

### 4.2 요청 문구 B — 단원 배정 (2차, 글자만)

- 교과 자료에서만 호출. 입력: 과목의 **단원 목록**(카탈로그 핵심평가영역 id·이름 + 성취기준 앞 3개 요약 50자) + 문항 목록(번호·발문 120자·보기 80자) + 자료의 시험 범위 표기
- 목적: AI가 단원 이름을 만들지 않고 **목록의 id로만** 답하게 한다

```text
한국 교육과정(2022 개정) 기준으로 각 문항이 어느 단원에 속하는지 아래 단원 목록에서 고르세요.
단원 이름이 아니라 **성취기준 내용**과 문항 내용을 비교해 판단합니다. 목록에 없는 단원을 만들지 마세요.
자료에 적힌 시험 범위: ${scopeText} (교과서 단원명이라 교육과정 단원 이름과 다를 수 있음 — 참고만)

[단원 목록]
- ${areaId}: ${단원명} — ${성취기준1 요약} / ${성취기준2 요약} / ${성취기준3 요약}
…

[문항]
- ${번호}: ${발문} (보기: ${보기들})
…

JSON만 응답: {"assign":[{"number":"1","areaId":0,"confidence":"high|low"}]}
```

## 5. 후처리 규칙 (코드)

### 5.1 정답
| 규칙 | 내용 |
|---|---|
| 모든 칸 보관 | AI가 준 정답 칸은 유형과 상관없이 모두 저장 (`choices·truth·texts·blanks·pairs·model`) — 유형 변경 시 복구용 |
| 낱말 → 보기 번호 | 선다형·양자택일형인데 `choices`가 비고 `texts`가 있으면 같은 글자의 보기 번호로 옮김 (검증 중 실제 발생: AI가 「무릎」을 texts로 반환) |
| 출처 보정 | 정답이 있는데 출처가 `none`이면 `ai`로 |
| 정답 없음 | 「⛔ 정답을 찾지 못했습니다. 정답을 입력해야 채점할 수 있습니다.」 — 저장은 되며 상태 「확인 필요」 |

### 5.2 단원 (교과 문항만) — 우선순위
1. 문항에 **성취기준 코드**가 적혀 있으면 그 코드의 단원 → 출처 `file`
2. **자료 단원 표기 속 후보**(표기 문자열에 이름이 들어 있는 단원 전부)에 **2차 배정 결과**가 포함 → `file`
3. 2차 배정이 **시험 범위 후보** 안 → `scope`
4. 자료 표기 후보와 2차 배정이 **어긋남** → 배정 결과 채택, `ai` + 「자료의 단원 표기(…)와 문제 내용이 맞지 않아 내용 기준 「…」으로 연결했습니다」
5. 2차 배정만 있음 → `ai` (시험 범위가 있는데 밖이면 「…시험 범위 밖입니다」)
6. 표기 후보 1개 / 시험 범위 1개 → `ai`
7. 모두 없음 → 단원 미지정 + 「단원을 정하지 못했습니다. 단원을 골라 주세요.」
- `confidence: low`이면 1~3의 확정 경로를 타지 않고 `ai`(교사 확인)로 내린다
- 단원이 정해지면 **그 단원의 성취기준 전체**가 문항의 성취기준이 된다 (`standardsBasis: unit`)
- 2차 호출이 실패해도 추출 결과는 살리고 「AI 단원 배정에 실패했습니다. 문항마다 단원을 골라 주세요.」

### 5.3 기초학력 (`track: basic`)
- 2차 단원 배정 생략, 단원·성취기준 확인 항목 없음, `standardsBasis: none`
- 학습 기능명(`skill`) 표시·필터 — 문제집 기본 이름·성격(기초학력)에 사용
- 교사가 교과 ↔ 기초학력 일괄 전환 가능. 교과로 바꾸면 단원 성취기준 재연결(단원 없으면 「단원을 골라 주세요」)

### 5.4 유형 변경 (`changeItemType`)
| 변경 | 정답 처리 |
|---|---|
| 선다형 ↔ 양자택일형 | 보기 번호 그대로 (양자택일형인데 보기 ≠ 2개면 경고) |
| 선다형·양자택일형 → 단답형 | 고른 보기 글자를 허용 답으로 (「무릎/무름」 → 「무릎」 쓰기) |
| 단답형 → 선다형·양자택일형 | 허용 답과 같은 글자의 보기를 정답으로 |
| 그 외 (예: → 진위형) | 정답 칸이 비면 「유형을 바꾸며 이 유형의 정답 칸이 비었습니다… (이전 유형으로 되돌리면 원래 정답이 살아납니다)」. 다른 칸 값과 출처는 유지 |

### 5.5 그림
- 문항별 `images[].box_2d`(0~1000 정규화)를 쪽 이미지에서 잘라 JPEG로 저장 (테두리 8px 여유). 24px 미만·범위 오류는 버리고 「그림 일부를 찾지 못해 넣지 못했습니다」
- PDF 렌더 주의: pdf.js v5는 JBIG2·JPEG2000 디코더(wasm) 경로를 지정해야 사진 마스크가 빠지지 않는다

## 6. 파생 문항 (다음 단계 기준)
- 기준은 **목표 학년 + 단원(영역)** — 난이도 슬라이더 쓰지 않음
- 학년 조정은 「다운그레이드」가 아니라 **목표 학년의 같은 영역 단원 성취기준에 맞게 변형·신규 개발**. 학년 간 차이는 깊이보다 범위(영역)일 수 있음
- 카탈로그상 초등 수학은 학년군이 달라도 같은 영역명(수와 연산·도형과 측정·변화와 관계·자료와 가능성) → 수학·과학부터 적용, 다른 교과는 교과별 검토
- 파생 문항은 `lineage.parentId`(원본) · `lineage.rootId` · `derivation`(방식)으로 연결
