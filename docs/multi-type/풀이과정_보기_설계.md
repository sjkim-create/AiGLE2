## 1. 무엇을 차용하고, 무엇으로 바꾸나

| Tecet | 아이글 (차용 · 대체) |
|---|---|
| ② 정답이 아니라 **과정을 영상처럼** — AI가 장면 스크립트(JSON) 생성 → SVG 애니메이션 + 음성 | **스마트펜 필기 데이터 재생 = 실제 손으로 쓴 풀이 과정**. 획(좌표·시간) 그대로 재생하고, 단계 구간마다 설명을 붙인다. AI가 그림을 "흉내 내는" 게 아니라 사람이 쓴 풀이가 그대로 재생됨 |
| 문제 이미지 위 동그라미·밑줄 표시 (이미지 인식 좌표) | 시험지 Ncode 좌표 위에 표시 — 문항·답안 영역 좌표가 시험지 배치 때 이미 확정되어 있어 **영역 인식이 필요 없다** |
| 정답 잠금 (끝까지 봐야 공개) | 그대로 차용 — 학생 모드에서 풀이를 끝까지 재생해야 정답 공개 |
| [모르겠음] — 재생 위치 직전 구간을 AI에 전달 | 2단계 — 단계(구간) 단위로 「이 단계 다시 설명」 |
| 학년·과목·단원 자동 추정 | 문제 은행 문항에 이미 학년·단원·성취기준이 있음 → 추정 불필요 |

**아이글만의 강점 (Tecet에 없는 것)**
1. **진짜 필기 재생** — 교사(출제자)가 펜으로 쓴 풀이 과정. 생성형 그림보다 신뢰도가 높고, 쓰는 순서·속도까지 보인다
2. **내 풀이와 나란히** — 학생 본인이 시험지에 쓴 필기도 재생할 수 있다 → 「모범 풀이 vs 내 풀이」 비교 (어디서 갈라졌는지)
3. **교사 검수 후 공개** — AI 오답 리스크를 교사 확인으로 막는다
4. **학습 이력** — 로그인·과제·채점 결과와 묶여 있어 다시 볼 수 있다 (Tecet은 공유 24시간)

## 2. 풀이 과정 데이터 (문항 단위)

| 항목 | 내용 |
|---|---|
| 필기 원본 | 풀이를 쓴 펜 획 목록 (획마다 좌표 · 시작/끝 시각). 스캔 이미지만 있으면 재생 대신 이미지 + 단계 설명 |
| 단계 | 1~N개. 단계마다 **제목 · 설명(자막) · 획 구간(시작~끝 획)** |
| 핵심 개념 | 1문단 (Tecet 「핵심 개념 요약」 차용) |
| 설명 수준 | 문항의 목표 학년 눈높이 (§3) |
| 작성 출처 | 교사 직접 / AI 초안 → 교사 확인 |
| 공개 상태 | 초안 · 공개 (교사 확인 전에는 학생에게 보이지 않음) |

**AI가 하는 일 (필기 → 단계)**: 획의 시간 간격·위치로 단계 경계를 제안하고, 필기 OCR 결과로 단계 설명 초안을 쓴다. 교사가 경계·문구를 고친다.
※ 획 데이터 형식 확인이 필요 — 본 폴더 `docs/9C_7B_..._strokes_parsed.json`을 우선 참고, 실제 풀이 필기 샘플은 전달받기로 함

## 3. 난이도 · 풀이 길이 정리 (질문 2 · 3)

**Tecet의 문제** — 「쉽게 / 적당히 / 짧게 / 맵게」는 서로 다른 두 축을 한 줄에 섞었다.
- 수준(눈높이): 쉽게 ↔ 맵게
- 분량(길이): 짧게 ↔ (자세히)
→ 「짧게」를 고르면 수준이 높아지는지, 「맵게」가 길어지는지 사용자가 알 수 없다. 실제로는 「쉽게」만 수준 조절이고 나머지는 길이 조절에 가깝다.

**권장안 — 두 축을 분리하고, 수준은 고르지 않는다**

| 질문 | 권장 | 이유 |
|---|---|---|
| ① 짧게 = 난이도 높음? | **아니다. 길이와 수준은 별개** | 짧은 설명은 「단계 수를 줄인 요약」일 뿐 어려운 설명이 아니다 |
| ② 난이도를 기본으로 정하나? | **수준은 문항의 목표 학년으로 자동 고정** — 학생이 고르지 않는다 | 아이글은 이미 「난이도 대신 목표 학년 + 단원」 원칙 (`AI_추출_설계기준.md` §6). 학년이 곧 눈높이 |
| ③ 학교급별 상·하로 나누나? | **나누지 않는다** | 상·하는 주관적이고, 같은 학년 안에서도 사람마다 다르다. 대신 학생이 「한 단계 쉽게」를 눌러 그 단계만 풀어 설명 (2단계 기능) |
| 길이 선택 | **기본 / 자세히** 2개만 (기본값 = 기본) | 「짧게」는 필기 재생과 맞지 않는다 — 필기는 이미 있는 그대로 재생되고, 길이는 자막(설명)만 달라짐 |

## 4. Tecet 약점 · 리스크 → 아이글에서 개선 가능한가 (질문 4 · 5)

| Tecet 약점 | 아이글 개선 | 가능 여부 |
|---|---|---|
| **생성 30~40초로 길다** | 학생이 요청할 때 만드는 게 아니라 **문항 저장(풀이 등록) 때 미리 만들어 둔다**. 학생은 대기 0초. 필기 재생은 생성이 아니라 저장된 획 재생이라 원래 즉시 | ✅ 가능 — 구조적으로 해결 |
| 학습 이력 · 오답노트 없음 | 과제 · 채점 결과 · 학생 모드 「내 과제」에 연결. 틀린 문항의 풀이를 다시 보기 | ✅ 가능 (이미 로그인·이력 구조 있음) |
| AI 오답 리스크 (고지 문구만) | 교사 확인 후 공개 (§2 공개 상태). 고지 문구도 유지 | ✅ 가능 |
| 로그인 없음 → 개인화 부재 | 학생 계정 · 학년 · 과제 기준 | ✅ 해당 없음 (이미 있음) |
| 손글씨 · 저화질 영역 인식 미검증 | 펜 = 좌표 데이터라 인식이 필요 없음. **스캔 답안은 같은 약점이 남음** (재생 불가, 이미지 + 설명만) | △ 펜은 해결, 스캔은 부분 |

**남는 제약 (구현 전 확인)**
- **AI 단계 나누기·설명 초안**: 프로토 배포본에는 Gemini 키가 없어 AI가 꺼져 있음 → 프로토는 샘플 데이터로 시연, 실호출은 로컬에서만
- **음성(TTS)**: Tecet은 음성 싱크가 핵심이지만 비용·서버 필요. **1단계는 자막만**, 음성은 상용 검토 항목으로 남김 (권장)
- **풀이 필기 확보**: 문항마다 누군가 펜으로 풀이를 써야 함 → 교사 부담. 대안: 문제집(출판사) 해설 필기를 일괄 등록, 또는 필기 없이 「텍스트 단계 풀이」만 먼저
- 문제 은행의 정답형 문항에만 적용 (서·논술 과제는 범위 밖 — 「문항=문제 은행」 원칙)

## 5. 학생 모드 화면 (질문 6)

**진입**: 내 과제 → 과제 상세(결과 확인) → 문항별 [▶ 풀이 과정 보기] (교사가 공개한 문항만)
※ 과제 결과 공개 후에만 노출 (시험 중 풀이 노출 방지)

```
┌ 문항 3 · 중1 과학 · 물질의 상태 변화 ───────────── [✕] ┐
│ ┌──────── 풀이 필기 재생 ────────┐  단계              │
│ │ (문항 이미지 + 필기가 써지는 캔버스) │  01 ● 조건 정리     │
│ │                              │  02   식 세우기     │
│ └──────────────────────────────┘  03   계산         │
│ 01 조건 정리 — 자막(설명)                 핵심 개념        │
│ ▶ ⏸ ⟲ ━━●━━ 1/3  1.0x · 1.5x · 2.0x    정답 🔒 끝까지 보면 공개 │
│ [기본 | 자세히]   [내 풀이 재생]                          │
└──────────────────────────────────────────────┘
```

| 기능 | 정책 |
|---|---|
| 단계 재생 | 단계마다 그 구간의 획이 써지고 자막이 바뀜. 단계 목록을 누르면 그 단계부터 |
| 재생 속도 | 1.0x / 1.5x / 2.0x |
| 정답 잠금 | 마지막 단계까지 재생하면 정답 공개. 한 번 공개되면 다시 잠기지 않음 |
| 내 풀이 재생 | 학생이 펜으로 제출한 경우에만. 같은 화면에서 모범 풀이 ↔ 내 풀이 전환 |
| 설명 길이 | 기본 / 자세히 (자막만 바뀜) |
| **태블릿** | 가로: 좌(재생)·우(단계) 2단 / 세로·좁은 화면: 재생 → 단계 목록 순 1단. 버튼은 손가락으로 누르기 쉬운 크기, 재생 캔버스는 두 손가락 확대·이동 |
| 스캔만 있는 문항 | 재생 버튼 대신 이미지 + 단계 설명 |
| 고지 | 「풀이는 선생님이 확인한 내용입니다. 궁금한 점은 선생님께 여쭤보세요.」 |

## 7. 결정 (2026-10-16 확정)

1. **풀이 필기의 주인 = 학생 본인 필기만** — 내가 쓴 필기를 단계로 나눠 재생하고, 단계마다 AI 설명(잘한 점 / 놓친 점). 바른 풀이는 끝까지 보면 열리는 텍스트로만 보인다(모범 풀이 필기 재생 없음)
   - 따라서 단계 나누기 · 설명은 **학생 답안마다** 만든다 → AI 채점 때 함께 생성해 결과와 같이 발송 (학생 대기 0초, Tecet 약점 해결)
   - 교사 검수 = 채점 확인 후 결과 발송 (기존 흐름 그대로)
2. **난이도 축 = §3 권장안** — 설명 수준은 문항 목표 학년 자동, 학생은 길이(기본 · 자세히)만 고른다. 「짧게 · 맵게」 · 학교급별 상하 없음
3. **음성 = 자막만** (TTS는 상용 검토)

## 8. 1단계 프로토 구현 (2026-10-16)

| 항목 | 내용 |
|---|---|
| 위치 | 학생 모드 › 내 과제 › 결과 확인 › 우측 답안 미리보기 아래 [▶ 풀이 과정 보기] |
| 샘플 | [수학] 민아의 일기 문항 1~3 — 1(잔액을 등호로 연결 못함 · 14초 멈춤) · 2(모두 잘함) · 3(식만 세우고 15초 멈춘 뒤 제출) |
| 필기 재생 | **프로토는 답안 글자를 한 글자씩 써 내려가는 흉내** — 실제는 펜 획(x · y · dt) 재생으로 교체. 획 데이터 형식: Ncode `strokes[].points[{x,y,f,dt}]` · `startTime` |
| 단계 데이터 | `solution: { level, unit, concept, steps[{ title, ok, line, pauseSec?, cues[{ w | pause, say }], basic, detail }], answer[] }` — cues = **장면 자막**(쓰는 순서대로 말하듯이, w = 그 장면에 쓴 필기), basic·detail = **정리**. 실제는 w 대신 획 구간 |
| 화면 배치 (v1.4) | 왼쪽 = 문항 지문 + 내 필기(장면 자막) + 재생 막대 / 오른쪽 = 풀이 단계(지금 단계가 펼쳐지며 **정리** 표시) · 핵심 개념 · 바른 풀이 |
| **실제 펜 데이터 (2026-10-16)** | 샘플 과제 「[수학] 유리함수의 그래프에서 식 구하기」 — `src/data/penSample_3-52-766-4.json`(원본 `*_strokes_parsed.json`에서 x · y · dt만, 획 208개 · 약 112초). 장면 cue = 획 구간 `s:[처음, 끝]`, 획 안 속도는 실제 그대로 · 획 사이 쉼은 최대 0.45초로 줄임, `mark` = 다 쓴 뒤 빨강. 머리글(획 0~13, 학년·반·번호·이름)은 개인정보라 좌표를 비우고 재생·미리보기에서 제외. 답안 미리보기도 실제 필기(SVG)로 표시 (`src/PenStrokes.jsx`) |
| **자막 간단히 · 자세히 (v1.6)** | 행동 중계(「~를 썼어요」) 자막 삭제 — 재생이 이미 보여 주므로 중복. 자막 종류 = 실수 · 멈춤 · 판단 · 이유만. cue에 `lv: 'detail'`(자세히에만) · `sayD`(자세히에서 바꿀 문장). 간단히는 평범한 구간을 자막 없이 재생. 유리함수 샘플: 간단히 6개 · 자세히 12개 (기존 20개, 그중 행동 중계 8개). AI 출력은 두 벌이 아니라 cue마다 수준 표시만 추가 |
